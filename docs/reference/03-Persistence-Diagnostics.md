# Persistence, recovery and diagnostics

## Persistent state inventory

| Location | Contents | Fresh install |
|---|---|---|
| Compiler `/data/<hash>.json` | Canonical identity, shape/material data, element template/links, generated assets and type allocation. | Empty named volume. |
| Mods `custom-element-designs.json` | Item type, creator, source construct, shared display name. | Created as designs are registered. |
| Mods `custom-elements-jobs/<requestId>.json` | Request/player/source/type, copy count, input bill, status, last error. | Empty directory created by mod. |
| Mods `custom-element-groups/<parentId>.json` | Construct/parent/type, child instance snapshots/active flags, links and lifecycle status. | Empty directory created by mod. |
| Existing game persistence | Gameplay definitions, inventories, element/construct/blueprint rows and native state. | Managed by the normal myDU server. |

The compiler writes immutable JSON with fsync and atomic replacement. Mod job/group/design files use
pending files and replacement. This protects individual files from partial writes but does not make
all game/file changes one transaction. Keep backup boundaries consistent across the whole server.

## CreationJob contract and ambiguous delivery

Request IDs and UI nonces are generated by the server. Jobs validate a 32-character GUID request ID;
repeat submission does not intentionally grant another batch. Fields are requestId, playerId, constructId,
itemTypeId, quantity, status, showResults, costs and lastError. The bill is frozen at export time.

Normal transitions are `pending` → `granting` → `completed`. Preparation/input errors leave a retryable
pending request with an error. Native item take/give is atomic inside the inventory transaction.
A crash during commit may leave `granting` even if the transaction committed; this state must be audited
against inventory/transaction evidence before repair. Do not change it to pending or replay it blindly.
Completed jobs remain useful evidence and can seed old creator/name records; do not casually purge them.

## ModuleGroup contract

A group includes parent, itemTypeId, construct, status, children and links. Each child has template key,
full ElementInfo snapshot and active flag. Disk files and the in-memory cache are copied on access so
callers do not mutate a saved snapshot unintentionally. Child lookup resolves parent ownership.
Lifecycle status includes deploying/deployed/failed, pickingup/storing/stored and destroying/destroyed.

Failed or interrupted multi-step deployment/pickup needs investigation against actual native rows.
Never regenerate child IDs or remove the group file without reconciling what still exists in game.

## Shared name contract

A design record contains itemTypeId, creator, sourceConstruct and name. Creator-only rename is checked
server-side; UI visibility is not the permission boundary. Names are trimmed, nonempty, at most 80
characters and reject control characters. YAML uses JSON-escaped strings. A shared rename updates the
single definition for all copies when clients reload that definition. Buyers do not receive independent
editable type names. The full Design ID remains unchanged after rename.

## Compiler HTTP interface

| Method/path | Request/result |
|---|---|
| GET `/health` | `{ "ok": true, "version": 1 }`. |
| GET `/shapes` | All saved Shape records, including assets/templates. |
| POST `/prepare` | Cells, meshes, materialNames, reservedIds, embeddedElements, embeddedLinks; returns a Shape. |

Validation failures use HTTP 422, invalid/excessive body sizes 413, unexpected compiler errors 500.
C# Compiler uses a 90-second HTTP timeout and surfaces response errors to the caller.
`/shapes` returns the full catalog, not just metadata; avoid repeatedly polling it on large worlds.
No authentication is implemented. Do not publish the port publicly.

## Mod action reference

These actions use the game's existing ModAction transport. IDs belong to CustomElements unless stated.
Normal players should use UI controls, which supply nonce/request validation.

| Action | Purpose | Access |
|---|---|---|
| SyncLoader 0 | Send catalog/resources, release synchronous login and finish pending work. | Native login. |
| 10 | Open amount dialog for a validated source. | Owner/legate. |
| 11 / 12 | Create 1 / 100 copies. | Owner/legate. |
| 13 / 14 | Open placed/inventory shared-name dialog. | Design creator. |
| 20 | Submit amount with dialog nonce and request ID. | Valid dialog/source. |
| 21 | Submit shared name with rename nonce/context. | Creator. |
| 22 | Acknowledge preview installation for the current session. | Matching player nonce. |
| 90 | Amount-dialog visibility diagnostic. | Matching dialog nonce/request. |
| 91 | Submit a scripted creation request through validated dialog generation. | Admin. |
| 92 | Reimport/refresh all definitions, bounds, templates and assets. | Admin. |
| 93 | Prepare/run native module lifecycle fixture. | Admin; validates source. |
| 94 | Run paid blueprint lifecycle fixture. | Admin; validates source. |
| 95 | Write capped preview diagnostic payload to server log. | Admin. |
| 96 | Install preview script/catalog for a connected player. | Admin. |
| 97 | Inject the bundled read-only UI probe. | Admin. |
| 98 | Restore missing blueprint module components on a validated owned construct. | Admin. |

Actions 93/94 alter a temporary fixture and clean it up; they must not be used casually on a production
world. Action 98 is narrowly targeted blueprint recovery, not general repair or a Maintenance Unit fix.
No player IDs, construct IDs, database credentials or Router invocation scripts from the original live
world are included in this kit. Use the target server's authorized administrative tooling.

## Failure evidence

Record timestamps, action/source/type IDs, relevant job/group JSON and server/compiler errors before
intervening. `TriggerAction` catches exceptions and emits both a native player message and
`CustomElements action failed ...` in logs. Preview startup records successful client acknowledgement
or installation timeout. Match these with native game logs; HTTP success is insufficient evidence.
